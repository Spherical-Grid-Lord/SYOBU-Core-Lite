人間承認ゲート  
相対変化が運用閾値（例 10%）を超える大幅なパラメータ変更は自動適用せず、オペレータ承認を要求します。承認は外部 UI または承認 API を通じて行い、承認結果は不変ログに保存されます。承認待ちのタイムアウトポリシーを設け、タイムアウト時は保守的なフォールバックを適用します。

介入ポリシーの例

小幅変更（相対変化 < 10%）: 自動適用

大幅変更（相対変化 ≥ 10%）: 承認要求

承認タイムアウト: 小幅フォールバック適用

監査ログ設計
必須フィールド  
すべての介入・承認・パラメータ変更は JSON 形式で保存し、以下を必須とします。

time : UNIX タイムスタンプ

event_type : 例 auto_intervention, approval_request, approval_result

zeta_before : 変更前の値

zeta_after : 変更後の値

reason : 介入理由（例 rotation_threshold_exceeded）

metadata : 候補スナップショット、回転数 N、サンプル数など

保存先と不変性  
監査ログは WORM ストレージまたはバージョニング付きオブジェクトストレージへ定期的に移送し、改ざん防止を確保します。
